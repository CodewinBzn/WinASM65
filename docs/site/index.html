WinASM65

A 6502 assembler, linker and debugger for Windows. It assembles for the NES, the Commodore 64, the Apple II, the Atari 8-bit, the BBC Micro and a dozen other systems, and it debugs the result live on the Mesen2 emulator, from a terminal monitor or from VS Code.

What it does

WinASM65 started as a single assembler executable and grew into a small tool chain. Each part is a separate project in WinASM65.sln, and each is usable on its own:

Assembler

Two-pass 6502 assembler: MOS syntax plus the common ca65, asm6 and NESASM forms, macros, local and anonymous labels, five CPUs.

Projects

A config.json assembles several units, links them through their symbol files, and combines them into one image, such as an iNES ROM.

Modules and linker

Relocatable .w65 modules, .w65a archives, a linker and an offline HTML viewer.

Targets

Executable formats and disk images for 15+ systems, from .nes and .prg to GEOS on D64 and tokenized BASIC.

Monitor

A terminal monitor that talks to Mesen2 through a Lua bridge: live RAM, breakpoints, stepping, patching.

VS Code

An extension: syntax colouring, diagnostics, hover cards, listing column, build task, and a full debugger.

The solution

Nine projects: four libraries or programs, their four test projects, and the abstractions the monitor is written against. The arrows are project references: everything depends on the assembler, and nothing in the assembler depends on the debugging side.

From source to a paused emulator

The path a source takes when you press F5 in VS Code, and where each step is documented:

  1. Assemble. Each unit of the project is assembled, then resolved against the symbol files of the units it depends on; each produces an object file, a symbol file and an in-memory listing. Assembly pipeline, Projects and segments.
  2. Combine. The object files and binary files (header, CHR data) are concatenated into the ROM, each padded to its declared size. Combining.
  3. Launch. Mesen2 starts with the ROM and the Lua bridge script; the bridge opens a TCP port. The bridge.
  4. Map. The listings become a source map: every emitted byte knows its file and line. Breakpoints set on source lines become addresses. Debug adapter.
  5. Debug. The bridge reports when execution stops; the adapter turns that into a stack frame, registers and memory. VS Code extension, Monitor.
